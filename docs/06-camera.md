# 06 — 카메라 시스템

현재 구현은 3개 모드와 이벤트 기반 시나리오 샷을 제공한다. Follow와 일반 Orbit 이동은 프레임
보간을 사용하고, 사건을 놓치면 안 되는 목적 샷은 첫 프레임에 목표 구도로 전환한다.

## 1. 모드

### Orbit (기본, 3인칭 자유 시점)
- 자체 구현 컨트롤: 포인터 드래그 회전, 휠 줌(거리 8~350m 클램프).
- polar angle을 제한해 바닥 아래로 들어가지 않게 한다.
- 현재 우드래그/두 손가락 팬과 씬 더블클릭 선택은 제공하지 않는다. 개체 선택은 HUD 목록을
  사용한다.

### Follow (개체 추적 3인칭)
- HUD 개체 목록으로 대상을 선택하면 타입별 거리의 후상방 시점으로 추적한다.
- 스프링-댐퍼 스무딩 (위치 damp 4.0, 시선 damp 6.0). 대상 소멸 시 Orbit 복귀.
- 휠로 추적 거리를 조절한다. 드래그하면 자유 Orbit으로 전환하며 HUD의 활성 모드도 함께
  갱신한다.

### FirstPerson (1인칭)
- 선택 개체가 있으면 해당 pose의 눈높이에 부착하고, 없으면 1.7m 높이에서 WASD/Shift로
  자유 이동한다.
- 포인터 드래그로 시선을 돌리고 팹의 전체 폭·깊이 경계는 넘지 않는다.
- 자기 메시 숨김, 헤드밥/레일 진동, 포인터락, 설비·벽 충돌 검사는 아직 구현하지 않았다.
  특히 워크스루는 운영 시연의 보조 시점이며 현재 상태를 피난 훈련용 충돌 안전 보행으로
  해석하면 안 된다.

## 2. 입력 매핑

| 키 | 동작 |
|---|---|
| `1 / 2 / 3` | Orbit / Follow / FirstPerson |
| `Space` | 일시정지 토글 |
| `[ ]` | 배속 감소/증가 (0.5→1→2→4→8→16) |
| `E` | 다음 개체 추적 (`Tab`은 표준 UI 포커스 이동에 사용) |
| `F` | 선택 개체 Follow |
| `WASD / Shift` | 1인칭 이동 / 달리기 |

전역 단축키는 버튼·링크·입력 요소에 포커스가 있을 때 동작하지 않는다. `Tab`은 브라우저 표준
포커스 순서를 유지하고 선택형 시간·카메라·개체 버튼은 보조기기에 현재 선택 상태를 전달한다.
600px 이하에서는 주요 조작 높이를 40px 이상으로 유지하며, 감소 모션 설정에서는 HUD 점멸과
전환 애니메이션을 억제한다.

## 3. 시나리오 디렉터 (자동 연출)

재난 데모의 핵심 — 사용자가 조작하지 않아도 카메라가 사건을 따라간다.

- `CameraDirector`: 시나리오 이벤트(`emergencyPhaseChanged` 등)를 구독,
  단계별 샷 시퀀스를 실행:
  ```
  gasLeak 예시: 설비 서비스 면 누출 플룸 근접 샷 → 광역 대피 샷 → 대피 인파 Follow
               → 휴머노이드 밸브 작업 → 비상구 집결 와이드 → Orbit 복귀
  ```
- 샷 정의는 시나리오 JSON의 `cameraCues[]`로 데이터화한다([08] 스키마 참조). 설정된
  `duration` 동안 후속 일반 태스크 배정 샷이 해당 phase cue를 덮지 않는다.
- 사용자 개입 뒤 자동 디렉터를 일정 시간 중단하고 재개 여부를 묻는 정책은 아직 구현하지 않았다.
- 목적 기반 휴머노이드 태스크는 `assigned`에서 로봇 Follow, `observing/interacting`에서
  작업 대상 Close-up, `reporting/returning`에서 다시 로봇 Follow로 전환한다. 재난 phase cue와
  같은 카메라 컨트롤러를 사용해 이동보다 현장 관찰·물리 조작의 가치를 먼저 보여준다.
- close-up 후보는 레이아웃의 주 통로, 열간 통로와 외곽 통로에서 고르고 설비 점유 사각형과
  시선이 교차하는 후보를 제외한다. 사람–로봇 인계는 두 pose를 잇는 선에 직각인 상부 구도로
  잡아 양쪽 움직임이 겹치지 않게 한다.
- 가스 경보의 첫 샷은 설비 중심이 아니라 실제 서비스 면의 누출점에 초점을 두어, 설비에
  가려지기 쉬운 분사 제트와 수직 플룸을 먼저 확인시킨다.
- 작업자 인지·양보·승인 장면과 로봇의 물리 작업 장면은 재난 phase cue보다 우선한다.
  이벤트 샷은 첫 프레임에 목표 구도로 컷하고, 일반 Orbit/Follow 조작은 기존 보간을 유지한다.

## 4. 구현 노트

- HUD의 카메라 모드와 선택 id는 zustand 스토어에, 실제 카메라 위치·각도는 렌더 루프 로컬에
  둔다. Follow에서 사용자가 드래그해 Orbit으로 바꾸는 경우에도 두 상태를 동기화한다.
- 세 모드는 현재 하나의 `CameraController`가 관리한다. 모드별 rig 인터페이스 분리는 장기
  리팩터링 후보이지 현재 구현 계약이 아니다.
- Follow/탑승 대상 pose는 PoseBuffer에서 직접 읽어 sim 이벤트를 기다리지 않는다.
